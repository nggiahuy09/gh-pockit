# 10k transactions

Measured on 2026-11-03 (W9 T4), on Flutter 3.35.6 / Dart 3.9.2 and SQLite 3.54.0, with the schema at v4. The dataset is 10,000 transactions
over the 24 months up to the run, 181 of them tombstones, from seed 42 (ADR-0025). These are the "before" numbers: nothing has been tuned
yet.

## On the phone — iPhone 15, iOS 27.2, profile build, 60 Hz

There were three measured runs, after one run that seeded the benchmark database. The tables give the median, with the range of the runs
in parentheses. The harness is described in ADR-0026.

| What the user waits for | Median |
| ----------------------- | -----: |
| Cold start, engine to first frame (`timeToFirstFrameMicros`) | 402 ms (371–429) |
| … of which the framework's own init | 72 ms (69–83) |
| Bootstrap to Home showing data | 133 ms (126–134) |
| Tap on the Transactions tab to the first row | 39 ms (38–40) |

The first launch also seeds the dataset. On that run, "bootstrap to Home" was 265 ms, so seeding 10k rows on the phone costs about 130 ms.

**Scrolling the list:** 30 flings with load-more, about 3,240 frames. The frame budget is 16.7 ms.

| Per frame | Build (UI thread) | Raster |
| --------- | ----------------: | -----: |
| Average | 3.05 ms | 1.63 ms |
| p90 | 3.31 ms | 2.26 ms |
| p99 | **44.3 ms** | 2.90 ms |
| Worst | **108 ms** | 4.28 ms |
| Frames over budget | **51 (1.6%)** (50–51) | 0 |

The Dart heap was collected about 580 times in the young generation and about 100 times in the old generation over the run.

## On the host — query tier

This tier runs on a MacBook in JIT, so compare it only with other host runs. The host case set also adds an account with 3 rows (ADR-0026).
The "repository" column is the first emission a bloc receives, mapped.

| Case | Rows | SQL + copy, median | Repository, median | Repository, p90 |
| ---- | ---: | -----------------: | -----------------: | --------------: |
| List, newest 50 | 50 | 1.92 ms | 2.30 ms | 2.60 ms |
| List, newest 500 | 500 | 15.7 ms | 16.0 ms | 16.8 ms |
| List, newest 2,000 | 2,000 | **78.4 ms** | **85.5 ms** | 97.6 ms |
| List, busiest account, newest 50 | 50 | 1.93 ms | 2.02 ms | 2.60 ms |
| List, quietest account, newest 50 | 50 | 2.50 ms | 2.82 ms | 2.95 ms |
| List, account with 3 rows | 3 | 2.34 ms | 2.87 ms | 3.34 ms |
| List, busiest category, newest 50 | 50 | 1.78 ms | 1.92 ms | 2.16 ms |
| Month totals (Home) | 1 | 0.18 ms | 0.33 ms | 0.36 ms |
| Month spending by category (Home) | 10 | 0.37 ms | 0.52 ms | 0.56 ms |
| Account balances (Home, Accounts) | 6 | 2.18 ms | 2.84 ms | 3.38 ms |

Seeding 10k rows on the host took 288 ms.

The plans are the same as in the W8 audit, and none of them scans the table:

- The list seeks the owner index, or the category index when filtered by category, with one primary-key lookup per parent.
- The month cases seek the owner index by the date range.
- The balances seek each account index.
- The account filter walks the owner index and filters as it goes, so an account with 3 rows reads the whole owner history to fill its page.

## What the numbers say

1. **The phone's raster thread has room to spare.** Raster p99 is 2.9 ms and no frame missed. The raster-heavy numbers from the Pixel_10
   emulator came from the emulator itself. The glass dock (ADR-0014) is not a cost at this size.
2. **The UI thread is steady with spikes.** The average frame is 3 ms, but 51 frames take 40–110 ms. The likely cause is the window that
   grows on every load-more (ADR-0011). On the host, a 2,000-row window costs 85 ms per emission, about 40 µs a row, and most of that is the
   statement and the copy, not the mapping. Each load-more and each write re-reads and rebuilds the whole window. This is unproven until T5
   lines the spikes up with the load-more events.
3. **Time to data is not a problem.** The first rows come 39 ms after the tap, and Home shows data 133 ms after bootstrap.
4. **The month aggregates need no covering index** (ADR-0021). Both stay under 0.6 ms.
5. **The balances and the sparse-account filter grow with the history.** They are 2.8 ms and 2.9 ms at 10k, against 0.5 ms and about 2 ms
   at 1k. The 50k run (T5) decides the covering index of ADR-0019 and the `UNION ALL` of W4 T5.
